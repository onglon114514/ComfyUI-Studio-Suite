# Danbooru 公共词典库接入方案

状态：首版独立词典、导入器、分页面板和 A/B 共享查词已经实现；全量精细分类、Task Agent 接入和独立共现包仍为后续阶段。当前实现与安装方式见 [公共词典使用说明](PROMPT_STUDIO_LIBRARY_zh-CN.md)。下文保留长期设计，不表示全部已完成。

## 目标与边界

建立一个离线、可浏览、可检索、可点击取用的公共 Danbooru 词典。Prompt Studio、A/B 双语对照和 Task Agent 共现参考共享同一查询层，不维护三份互不一致的词表。

现有 `prompt_studio/storage/group_tags` 保持原样，继续作为用户的快捷编辑区。公共库更新不得重写它；只有用户主动执行“加入我的快捷标签”时，才通过现有管理接口写入用户指定分组，并处理重名确认。

“全集”必须明确数据源、快照日期、纳入条件、缺失字段及覆盖量。现有本地数据的并集不等于 Danbooru 最新全部有效标签；没有译名、分类或共现的条目也要保留并明确标注，不能用推测填成已确认数据。

## 两层分类

1. 原始类别保留 Danbooru 的 general / artist / copyright / character / meta 编码；未知来源保留 unknown，不从括号样式猜人物身份。
2. 面向人类浏览的语义分组采用多标签：外观、服装、姿势、表情、场景、构图等。一个 tag 可以进入多个组；人物与作品用独立的关系字段，不能挤入服装或外观分类。

官方类别依据：[Danbooru TagCategory 源码](https://raw.githubusercontent.com/danbooru/danbooru/master/app/logical/tag_category.rb)。官方标签、别名与蕴含关系是独立结构：[Tag 模型源码](https://raw.githubusercontent.com/danbooru/danbooru/master/app/models/tag.rb)。本项目的语义分组不是宣称已有全量官方分类。

子代理适合按领域和批次提出分类建议，输出 evidence/source/review_status。已有可信映射优先；规则只做明确匹配；歧义进待审核队列。不能让 LLM 一次生成几十万条分类、译名和关系后直接当权威词典使用。

## 数据布局

以下为长期拟定结构；首版实际使用 `catalog-<版本>.sqlite3`，共现与词条暂在同一数据库，通过原子切换 manifest 更新：

```text
resources/danbooru_library/
  categories.v1.json       分类定义与来源，不存全量 tag 按钮
  manifest.json            数据版本、来源、哈希、覆盖范围与字段统计
  catalog.sqlite3          标签、译名、分类、别名及必要搜索索引
  cooccurrence.sqlite3     较大的可选共现包，可独立安装与更新
prompt_studio/storage/
  group_tags/             原样保留：用户快捷标签
  dictionary_overrides/   拟新增：用户译名/分类纠错与收藏引用
```

机器翻译缓存、人工确认译名和来源译名分开存；查询时允许显示来源与审核状态。HY-MT 缺词补译不自动晋升为权威译名，不自动写回公共数据包。用户可主动确认并存入自己的覆盖层。

标签以 canonical 名称和来源 ID 关联，展示名称与写入提示词的格式分开；保留别名、停用/替代信息。统计必须记录各自语料来源及时间，不能把本地训练集 Count 冒充全站 post_count，也不能直接相加不同语料的频次。

共现关系只表示一起出现，不等于同义词、翻译或必然属性。界面将“译名”“别名”“常一起出现”分栏展示。缺少源 tag 频次或样本总量时，只展示共现次数，不伪造条件概率/关联强度。新索引从两个方向查询相关 tag，按实际次数排序，不能先截断输入文件的前几行再排序。

## 查询与交互

拟提供轻量 Python 查询模块及 ComfyUI HTTP 包装：status、categories、search、lookup、detail、related。模块本身不启动 LLM，也不导入重型任务执行器。

- 新增“词典库”入口，与原快捷分组并列，不替换现有收藏或自定义编辑区。
- 分类树、中英文/别名搜索、标签卡片和按需详情。常见标签与用户最近使用优先展示，但原始类别和来源可筛选。
- 点击“查词/相关”可从当前 tag 直接定位条目，看到译名、canonical 名、分类及共现结果。
- 插入目标显式显示为正向、反向或当前 XML 字段；不靠最后一个失焦输入框猜目标。用户只点浏览时不修改提示词。
- XML 模式必须复用字段草稿桥接流程；当前 `newbieXmlWizard.js` 通过 bridge input 同步字段草稿，不能直接覆盖整个正向框，否则会破坏 XML 字段编辑。
- A/B 通过同一 lookup 查询本地译名，未命中再沿现有 HY-MT 路线处理。Task Agent 只取少量相关记录，不把完整数据库拼进上下文。

## 性能约束

默认每页 40 项，接口硬上限 100 项；分类只传节点计数，不携带全部子项。关键词采用防抖、取消和请求序号校验；切换分类、节点或关闭面板后丢弃旧响应。详情、共现按点击加载，不为每张卡片提前请求。

数据库只读查询走参数化 SQL、前缀/全文索引和有界缓存。中文检索索引单独验证，不能把对所有译名做 `%词%` 全表扫描当作大词库的最终方案。共现查询使用 seed 索引，不在每次打开面板时解析 CSV。

关闭词典面板后不保留庞大卡片 DOM，不增加全局轮询或动画。不得为了显示词典就预热 LLM。只读查词与模型推理分开，缺词补译继续服从跑图队列保护。

索引在明确的安装/导入动作中构建，不在 ComfyUI 启动、开编辑器或跑图途中自动构建。新索引先在资源所在磁盘生成临时版本，校验成功后切换；不把大临时文件放到 C 盘默认目录，不删除仍被查询使用的旧版本。构建失败保留旧索引可用，并显示磁盘空间需求。

## 实施顺序

1. 清点真实数据，建立来源清单、分类骨架及 unknown 待整理组。本轮交付此阶段，详见资源审计文档。
2. 实现可复现的流式导入器与离线 SQLite 查询服务；核对去重、分类/译名覆盖率、共现双向结果及来源。导入不改原文件。
3. 做独立词典面板，打通搜索、浏览、详情、插入当前目标及加入快捷标签，再与 A/B 对照共享查询入口。
4. 让 Task Agent 的统计/共现检索接入同一索引；保留资源未安装时的降级，避免引入硬依赖。
5. 分类分批审核与补齐，评估官方数据快照获取、来源声明及分发条件后再生成可分享资源包。大包沿用 HF 资源托管思路，节点代码不内嵌巨量数据。

## 验收清单

- 导入、更新前后原 `group_tags` 文件哈希完全一致；重复导入幂等，取消/损坏输入不破坏旧索引。
- 每个来源有实际导入数、拒绝数、合并规则及缺失字段统计；来源不可核实时明确标为未知。
- 中英文、别名、特殊括号、空查询及停用标签能正常查询；缺译名不报旧翻译服务错误。
- 对照不改上方实际提示词，已保存对照重开保留；普通正/负向与 XML 字段插入分别回归。
- 共现不自动给人物追加作品外观，不把人物/作品统计误当普通服装建议；关联类别可显式筛选。
- 在本机全量已有数据上测试首次/热查询延迟、内存、响应大小、可见 DOM 数；指标记录实测值，不提前承诺亚秒级全量构建。
- 连续搜索、翻页和开关至少 50 轮，无持续增长的 DOM/监听器；关闭时无词典后台请求；同时跑图时不启动翻译模型。
- 旧快捷标签、XML、A/B、队列保护及现有浏览器减负回归全部继续通过后，才同步运行目录及考虑发布。
